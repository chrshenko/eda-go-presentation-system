# Запуск сборщика

## Проверенный вариант: Codex

Попросите Codex найти bundled runtime через load_workspace_dependencies. Используйте его Node и пакет @oai/artifact-tool. Пакет не является самостоятельным веб-приложением и не содержит API-ключей.

Сборщик загружает `@oai/artifact-tool` стандартным import. Для окружения Codex можно связать корневой node_modules пакета с bundled node_modules. Сам runtime в архив не включён. Не устанавливать случайную одноимённую библиотеку из непроверенного источника.

Альтернатива — задать ARTIFACT_TOOL_PATH абсолютным путём к entrypoint доступного runtime. Если среда не предоставляет библиотеку, использовать каталог PPTX и другой инструмент создания презентаций; скрипт без зависимости не запустится.

## Шрифты

Установить три TTF из fonts/. Если шрифты уже установлены, перезапустить редактор. YS Display Cond Black, YS Text Regular и YS Text Medium могут иметь разные внутренние имена; точные имена и SHA-256 находятся в fonts/manifest.json.

## Команды

Запускать из корня пакета. Относительные пути к изображениям в JSON считаются от корня пакета.

```sh
node scripts/validate.mjs examples/brief.json
node scripts/build.mjs examples/brief.json output/presentation
python3 scripts/inspect-pptx.py output/presentation.pptx
```

Валидатор брифа и инспектор PPTX не требуют artifact-tool. Инспектор использует только стандартную библиотеку Python 3. Выходные файлы не коммитить в рабочий репозиторий автоматически.

## PDF и данные диаграмм

Сборщик вызывает Python 3 (переменная PYTHON_BIN, иначе python3), чтобы вложить Excel-книги в нативные диаграммы. Встроенный PDF-экспорт используется при доступности; если он не работает, сохраняется PDF-снимок из JPEG 1920×1080 того же финального рендера. В таком PDF текст не выделяется; PPTX остаётся редактируемым. Это позволяет избежать подмены шрифтов сторонним конвертером.

## Что автоматизировано

JSON → структурная проверка → раскладка одного из 20 макетов → PPTX/PDF → PNG-превью. Превращение свободного текста в JSON выполняет AI в чате; в сборщик не встроена модель. Визуальный контроль остаётся обязательным.

## Проверка и выпуск

`npm test` проверяет ограничения брифа. `python3 scripts/check-export.py output/presentation.pptx output/presentation.pdf` проверяет декодирование картинок и число страниц; для него нужны Pillow и pypdf. Сборщик регистрирует приложенные TTF напрямую для рендера; установленные шрифты нужны также редактору PowerPoint.

После пересборки каталога/примера и визуальной приёмки: `python3 scripts/package-release.py ../eda-go-presentation-system-v1.0.1.zip`. Скрипт обновляет хеши и исключает среду исполнения и временные файлы.
